# 数据范围、模型与建设路线

## 数据域清单

把以下表当作接入计划；“目标字段”是分析模型需求，尚未接通的源字段和接口需要从后台或官方契约核实。公司录入不等于账号有权限，也不等于已经可全历史读取。

| 数据域 | 目标粒度与字段 | 主要用途 | 当前覆盖 |
| --- | --- | --- | --- |
| 商品、款式、分类、品牌、单位 | 公司×SKU，启用状态、属性、价格、单位换算 | 商品结构、分类贡献、数据质量 | catalog全目录及缺项可执行；类型/货权需映射，单位不自动换算 |
| 销售订单、明细 | 公司×订单×明细，数量、状态、下单/付款/发货/修改时间、渠道、成交分摊 | 销量趋势、渠道结构、履约 | 当前页限定范围有效明细/月件数/日序列可执行；归档全历史、金额及消耗未验收 |
| 库存、占用、冻结、仓库 | 公司×仓库×SKU×快照时刻，实际/虚拟/锁定/可用的边界 | 缺货、调拨、履约、库存健康 | 主仓在售及实物扣占用核对可执行；锁定/全仓履约及历史未验收 |
| 库存流水、出入库 | 公司×流水明细，业务关联、时间、数量、原因、成本 | 真实消耗、盘差、周转 | 仅当前未结采购/加工关联收货已接；完整库存流水、出库消耗及成本未接 |
| 采购订单、入库、在途 | 公司×采购明细，订购/已收/取消数量、供应商、仓库、状态、计划/实到日期 | 补货去重、ETA、交期学习 | purchase-lines/supply-review当前非归档未结SKU与收货核对可执行；采购头总量额外补充未接；有效实物供给/交期/归档未验收 |
| 加工单及生产批次 | 公司×加工明细/批次，加工前后 SKU、投入、已收、剩余、业务关联、工序事件 | 加工未结核对、半成品和补产 | manufacture-lines/supply-review未结产出、原料单号关联及收货核对可执行；逐行BOM、实耗、批次及工序事件未接通 |
| 售后、退款、退货入库 | 原订单明细关联、数量、状态、完成时间、可重新销售量 | 净销量、质量问题、回收供给 | 未接通 |
| 供应商及采购规则 | 公司×供应商×SKU，交期、MOQ、批量/包装、产能、成本 | 可执行补货、资金约束 | ERP政策接口/交期学习未接；第三批可读取有来源的本地参数与假设进行条件试算 |
| BOM、预包/套装关系 | 公司×套装×组件×版本/生效时间，用量、单位 | 组件需求、共享库存分配 | 页面可见组件集合；映射及历史版本未验证 |
| 店铺/渠道、客户分组 | 非个人身份的业务 ID、类型、渠道、地区分组 | 渠道对比、客户结构 | 订单可能含相关字段，尚未验收指标 |
| 成本、应收应付及经营费用 | 业务关联、金额、币种、期间、确认规则 | 毛利、资金占用 | 未接通，需定义边界后接入 |

不为“全数据”无目的保存联系人、手机号、详细地址；经营分析按业务 ID 和汇总维度建模。不能由缺失的财务数据生成公司完整利润。

## 推荐数据结构

分开保留源字段含义与规范化指标。先以本地 SQLite 建设必要数据，量级/并发超出能力时再考虑其他数据库；首版 skill 不创建数据库或全量同步任务。

- `ingestion_run`：run ID、公司、数据域、源接口/契约版本、筛选条件、查询开始/结束、覆盖期间、页数/行数、排除数、完整性/失败原因、水位。
- `sku`、`warehouse`、`supplier_sku_policy`、`bom_component`：主数据、单位和生效版本。
- `sales_order`、`sales_order_line`：源状态及规范化状态、主子关系、事实日期，唯一键至少公司+订单/明细 ID。
- `inventory_snapshot`：公司+仓库+SKU+快照时刻；保留各库存桶和源可用字段，避免把公式相似的字段合并。
- `inventory_movement`、`purchase_line`、`receipt_line`、`aftersale_line`：各自唯一业务明细及关联键；不盲目互相相减。
- `daily_demand`：公司+SKU+渠道/仓库+日期+口径版本；有 coverage 状态，区分零销量、缺数据、缺货限制销售。
- `analysis_run`、`forecast_run`：数据 run、模型/规则版本、历史截点、参数来源、情景、区间及结果。原始数据和预测结果分开。

源接口返回未知字段不要全部落盘。先白名单投影并保留必要追溯 ID；需要源证据时保留脱敏字段样本/契约。聚合每次可由明细重算。事实计算用代码/SQL，模型解释只读取所需聚合和异常记录。

## 同步与完整性

1. 首次按实际需求明确期间（例如先 90 天日明细），先盘点归档入口、数据量、权限、字段和限流；本次不自动拉取全历史。
2. 每批检查分页总数、唯一键、公司、单位、状态和筛选生效；跨域关联后核对总量，异常明细单独标记，不静默丢弃。
3. 只有确认源端支持修改时间/水位后才实现增量。使用重叠窗口、幂等 upsert 和成功批次提交水位；失败保持旧水位。没有修改水位就按限定时间分片重读，并记录覆盖限制。
4. 订单取消、售后和在途变更可能发生在老订单上。结合未结单重读、售后更新、周期重核对已结历史；不能只抓最近下单数据或假定 7 天回看覆盖所有修改。
5. 查清删除/禁用/归档语义；没有 tombstone 时采取范围内重核对，不能因一页不见就判定删除。成功且范围完整后才替换该范围事实。
6. 库存快照新增时间版本；不从当前库存倒推过去缺货天数。实际入库和未收采购量对账，避免采购量与入库量重复作为供给。
7. 记录不同源的读取时刻。跨域时点不一致要在结果中呈现，必要时刷新关键库存/在途；不声称事务一致。
8. 小批量、低并发、适度重试；登录/权限/结构错误停止，避免无限重试。采用 SQLite 事务和分析固定截点得到可重现本地结果。

## 建设顺序与验收

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| A：本版 skill | 已有查询入口、指标语义、数据域清单、分析与预测规范 | skill 结构校验；已有查询可调用；未接通能力明确 |
| B：分析数据底座 | 全量销售明细、日序列、仓库/库存字段、BOM映射、覆盖及增量机制 | 全期对账、拆合单/套装去重、重跑幂等、缺数据不填零；全历史必须先验证归档 |
| C：库存健康 | 近期销量、实际库存、覆盖天数、共享组件风险、缺货候选 | 库存桶/单位校验，缺货限制销量识别，结果可追溯到 SKU×仓库 |
| D：补货建议 | 采购在途/ETA、入库对账、交期和补货约束、确定性预测基线 | 到货前缺口和下单日可解释；时序回测；缺关键参数仅输出情景 |
| D2：加工与半成品 | 加工明细/收货对账、货权、阶段转换、剩余工艺周期；必要的批次报工 | 未结账面与物理在制分开；暂停/恢复和工序约束经工艺确认，不能用单头直接排到员工 |
| E：经营诊断 | 售后/渠道/商品结构/毛利等经验证指标和综合建议 | 每项指标有数据覆盖、口径、核对样例；不以部分数据代表全公司财务 |

自动日同步、主动预警、可视化看板和正式开放平台接入是后续部署选择；单独按用户需要推进，不在 skill 创建时擅自启用。
