# 需求预测与补货规则

## 输入与粒度

以 SKU×仓库为最终补货粒度。若渠道只对应共享仓，不虚构渠道库存；先聚合需求再分配。销售排名的套装粒度与组件采购粒度分别展示。

必需输入：连续日期的有效销售/实际消耗、完整性标记、实际可履约库存及占用边界。确定采购建议另需有效采购在途、剩余数量、预计可用日期、交期、MOQ/包装倍数、供应商能力和预算约束。未录入字段请求用户提供或做明确假设的情景。

大漆陶瓷补产另需加工未收及预期入库、现存半成品、前后 SKU/工艺关系和剩余关键路径；采购成品、采购胚体及厂内补产交期不能互换。读取 [工厂参考](factory-analysis.md) 后再提出停产、插单、启用半成品或长周期预警建议。

已有完整日销售序列、主仓字段及采购加工未结核对；第三批 `replenishment-plan` 已支持直接订单需求基线、逐日缺口和参数化补货/补产情景，执行契约见 [情景模块](replenishment-plan.md)。本文件保留完整需求、BOM、消耗及实际供给的建设规则，不能将条件试算称为完整预测或可执行采购政策。

## 先明确需求及库存

- 月订单销量沿用已确认口径；补货消耗还包括赠品、换货、补发、非销售领用，另建消耗序列。退款不必然返还库存，只有可用退货实际入库才成为供给。
- 若订单明细已含套装组件，不同时对父套装再展开；映射销售根明细和库存消耗明细，BOM 用当期版本。套装组件需求 = 根销售套数×组件用量，展开一次。组件合并普通单品需求，检查单位换算和 BOM 缺失/循环。
- 共用组件统一分配，不能分别给每套装全部可用量。存在预包成品时验证“成品库存+未预包组件”的边界，防止把已被占用组件再加回供给。
- 区分实际库存、虚拟库存、冻结/质检、订单分配、库存锁定。不同占用字段是否重叠要核对；不能把含虚拟量的 `orderable` 当成实物供给。
- 构造 `A0` 为已核实、扣除当前承诺后的实际可履约量。若源字段已扣订单占用，不再扣未发货订单；预测的未来需求此时只包含新增需求。若采用未扣承诺的实物量，则显式加当前承诺消耗，并与新增需求分开。

## 建立可解释基线

在每日完整覆盖范围内补齐日历：已确认有数据覆盖而没有订单的日期才填 0，未知日期保留缺失。先比较最近 7/28/56 个完整日的平均每日需求和活动变化；这些是分析候选窗口，不是已确定企业补货政策。当前未结束的一天分开显示，不直接作为完整日参与均值。

优先使用容易复核的移动平均/近期加权基线，记录权重、窗口和选择原因；以时间向前的滚动验证选择。只有样本支持且基线验证不足时再增加星期效应、间歇需求模型或季节性模型。不要默认商品都是稳定日销，也不把一次大客户订单均摊成固定长期需求。

按 SKU 区分稳定、趋势、间歇、新品、活动/大单和长期缺货。缺货期销量受供给约束，不能用低销量证明低需求；没有库存历史只能标注“可能受缺货限制”。有完整历史可在有货期建基线，并将未满足需求作为独立估计，不能改写事实销量。

用按预测时点截断的数据做滚动回测；只能使用该时点已知的库存、状态、采购 ETA 和活动信息。没有状态/ETA 历史时标明回测受限。计算 MAE/偏差，跨 SKU 加权误差分母为零时返回不适用；不要只用高销量 SKU 的误差掩盖缺货关键品。

给预测区间需实际历史误差或有说明的情景；不得把高低情景称为统计置信区间。样本不足时给参考需求和不确定性，不编造精确缺货日。

## 计算风险和补货

为每个日期计算：

`P_t = A0 + 截至 t 已确认可用的新增到货 - 截至 t 预测新增消耗`

在途仅取有效未收数量，按预计可销售日期而非仅预计运输到达日期计入。延迟或 ETA 不明单独列情景，不能在今天可用库存里相加。当前已存在缺口必须立即呈现；找到首次 `P_t < 0` 的日期作为基线缺货日，并给最迟可用到货日、预计前置缺口。仅“库存÷日均量”的覆盖天数不替代逐日模拟。

以交期 `L`、复核周期 `R` 和目标安全库存 `S` 定义目标：

`初步补货量 = max(0, 未来 L+R 天新增需求 + S - A0 - 在该期间有效的已确认到货)`

检查区间总量之外的到货时序：晚到的采购即使足够覆盖总量，也不能消除此前缺口。按交期回推最迟下单日；若已晚于该日期，区分加急、调拨和普通采购，列明各自数据约束。

`S` 优先用公司已有规则或经回测的服务水平规则；缺规则时提供由用户选择的安全天数情景。交期优先用供应商×SKU 实际采购至可用入库历史，并识别分批入库和异常；不存在时使用用户提供参数。不要将未经确认的“交期 14 天/安全库存 7 天”输出成公司事实。

将正数补货量向上按已核实的采购单位/包装倍数取整，并满足 MOQ。预算/产能/最小金额约束需另做分配；不得只算完单 SKU 后宣称整份采购清单可执行。MOQ 造成超储时展示影响，禁止用“销量为零”的除法给无穷覆盖或硬推采购。

## 输出与降级

输出列：SKU、仓库、实际净可履约量、日需求/预测窗口、有效在途与 ETA、交期及参数来源、风险日/到货前缺口、最迟下单日、建议数量及单位、包装/MOQ 调整、情景/置信程度、建议动作。

数据不足时仍输出已验证库存/销量与待补项；缺在途就标“未扣已采购量”，缺交期只给所需到货日期，缺 BOM 就不生成组件采购量。将所有假设放在对应情景旁。输出计划建议，不创建采购单或修改 ERP。
