# 分析工作流与交付格式

## 将问题转成数据任务

| 问题示例 | 数据和计算 | 首版实际执行方式 |
| --- | --- | --- |
| 现在有多少在售商品？ | 全商品启用状态+主仓可用库存，SKU计数 | 直接执行已有入口 |
| 本月销量最好的商品？ | 有效订单明细，SKU聚合 | 直接执行已有入口 |
| 近期日销量和当前主仓库存错配？ | 全范围有效明细日序列、主仓库存、分类/货权/单位 | 读sales-stock.md，调用sales-daily/stock-sales；缺项只给核对候选 |
| 销量为什么涨/跌？ | 完整日明细、同期可比期间、渠道/分类、活动、库存缺货及大单 | 补齐日序列，分解数量贡献；没有活动/缺货证据就保留待验证原因 |
| 哪些商品滞销或积压？ | 库龄/入库、库存历史、近期真实消耗、启用/新品状态、成本 | 接通库存/消耗历史；零销量且有库存仅作候选，不直接判断滞销 |
| 哪些快缺货、采购或补产什么？ | 实际库存、需求日序列、BOM、在途、ETA、供应商/工艺周期、约束 | 读replenishment-plan.md，执行条件情景；缺商品/库存不模拟，缺周期不编建议，未确认供给不直接扣减 |
| 采购是否重复、供应商是否拖期？ | 有效采购剩余量、分批入库、计划与实到、同组件聚合 | supply-review已可核对当前未结；日期及组件缺项可见，未结年龄不直接算拖期 |
| 哪类商品/店铺赚钱？ | 成交金额、成本、售后、费用分摊及确认期间 | 先定义金额和成本；字段不足就只做销量贡献 |

## 分析顺序

1. 确定事实覆盖和可比性。比较月度趋势时将本月未完期间与相同已过天数或完整月分开展示，避免把月初销量与上月全月直接下结论。
2. 按用户问题依次展开商品、款式、分类、渠道和仓库，不机械生成所有维度报表。将大单影响、价格/数量变化和缺货期间单独列出。
3. 输出贡献度和异常量；只对有证据的异常进一步解释。单指标“高销量”不等于高毛利，“低销量”不等于库存无风险。
4. 给可执行动作及其优先级，用缺口规模、到货前风险、资金约束和数据可靠性说明顺序。紧急库存风险先处理，再优化长期结构。
5. 对未验证解释列出能判定它的数据或下一步只读查询；不要求用户泛泛提供“更多数据”。

## 回答模板

先给一至三条主要结论和优先行动，然后给表格或所需对比。保持以下信息可见：

- **事实**：数值、单位、期间、SKU/款式/仓库/渠道范围、排除口径。
- **证据**：数据域、数据获取起止时间、覆盖和完整性、来源 run 或本地报告，必要的内部明细号。
- **解释**：证据支持的变化；待验证原因分开标记。
- **预测/建议**：方法、样本、参数来源、情景及误差/限制；没有预测时不添加此项。
- **动作**：做什么、为什么、最迟什么时候、由什么约束决定；不得宣称采购已经执行。

图表用于日趋势或维度比较；库存及补货清单优先用表格。只在图表比文字更清楚时创建，不为简单计数制作看板。

## 接入和指标扩展的完成条件

在项目中实现新入口或计算逻辑时，遵循现有 AGENTS.md 的最小改动要求。先记录真实契约与口径，再写必要代码；用脱敏或构造明细回归重复、失效、缺字段、跨期和单位边界。只读接口做小范围真实核对，检查分页与聚合一致，再标记能力已可用。

缺货预测增加带已知输入和期望边界的验证：在途晚到、订单占用重复扣除、虚拟库存、套装共用组件、赠品消耗、MOQ/包装及零需求。回测使用向前滚动时间切分。通过已有检查后不无限增加无关测试。

本 skill 是能力规范和任务入口，不保证每个设计数据域都已接通，也不代替实际 API 权限、归档覆盖和企业补货参数的核对。
