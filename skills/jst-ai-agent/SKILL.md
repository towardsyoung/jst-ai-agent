# jst-ai-agent

把公司业务数据转成有证据、能解释、可行动的分析。先核对可用数据，再选指标和方法；让确定性代码算数，让语言模型解释原因、比较情景和提出建议。

## 先定位能力

通过本 skill 的 `scripts/query.sh` 调用配套只读工具。入口支持项目相对位置、打包后的 `runtime/` 或 `JST_AI_HOME` 指定的工具目录；不依赖开发者电脑路径。读取与计算代码在项目唯一维护，交付包可附同源运行代码。

公司和用户从本次登录会话自动识别，不绑定任何公司或员工。切换到目标公司后重新查询；一次查询固定使用启动时的身份，不跨公司拼接事实、规则或历史报告。回答先注明结果的 `company_id`、数据时间和范围。

当前认证适配器仅支持 macOS Chrome，默认 Default Profile，可加 `--chrome-profile "Profile 1"`。Windows/Linux 认证、WorkBuddy 自动安装和一键登录尚未实现；技能通用化不等于这些环境已验收。首次接入或切换后可用 `scripts/query.sh session-check` 核对身份与商品接口权限；它不证明全部数据域可读。客户正常登录，不要求复制 Cookie。详情见 [身份、公司切换及安装](references/session-access.md)。

| 问题 | 当前入口 | 能力边界 |
| --- | --- | --- |
| 当前在售商品数量 | `scripts/query.sh onsale-count` | 普通商品与组合装全量计数、分别展示 |
| 本月/某月销量最好 | `scripts/query.sh sales-top [--month YYYY-MM] [--limit 10]` | 有效销售订单件数，按 SKU 排名 |
| 登录是否可用 | `scripts/query.sh session-check` | 自动识别当前身份并验证商品接口可读，不证明其他数据域完整 |
| 商品目录、当前主仓库存字段 | `scripts/query.sh catalog [--sku SKU]` | 全目录读取后白名单投影；类型、单位、货权缺项标记 |
| 有效销售明细、SKU日销量 | `scripts/query.sh sales-lines/sales-daily [--days 30或--month YYYY-MM] [--sku SKU]` | 当前订单页限定范围完整读取；不是出库消耗或全历史 |
| 销售与库存错配、主仓不足核对 | `scripts/query.sh stock-sales [--days 30或--month YYYY-MM] [--sku SKU]` | 核对候选；分类、单位、货权和供给缺项可见，不直接判滞销/采购量 |
| 采购/加工未结、旧单及分批收货核对 | `scripts/query.sh supply-review [--kind purchase/manufacture] [--age-days 90]` | 当前非归档未结SKU、收货、剩余及缺日期候选；不是实物在途/真实在制积压 |
| 采购/加工指定单据及原料关联 | `scripts/query.sh purchase-lines/manufacture-lines [--document-id 单号] [--sku SKU]` | 加工原料与产出按单号关联；逐行BOM/实耗/工序未验证 |
| 未来库存时序、补货/补产条件试算 | `scripts/query.sh replenishment-plan [--days 56] [--horizon 30] [--scenario-file 参数.json]` | 完整日直接订单基线、逐日缺口及参数化数量/日期；缺商品规则/批次/周期时标缺项，非可执行采购或员工排程 |
| 工厂六类痛点、半成品及补产可行性 | 读取工厂参考及当前接入证据 | 复用前两批事实；车间批次、单位/货权和工艺周期仍需确认 |
| 完整周转、确定缺货预测、可执行采购清单、售后、利润 | 按下方参考选择数据 | 尚无完整执行链；不能用条件试算或账面剩余冒充已经实现 |

从 skill 所在目录运行相对命令，或用其绝对路径；勿假定用户当前工作目录就是项目目录。入口路径不存在时报告配套工具需要安装，勿搜索或自动切换到其他 Profile 的 Cookie。

## 按任务加载参考

- 查询或解释已有指标：读 [默认指标与已验证接入](references/company-metrics.md)。
- 读取商品、销售日明细，或分析销售与当前库存错配：读 [销售与库存核对流程、规则及示例](references/sales-stock.md)。新命令默认近30自然日，展示10行；完整结果可用 `--output` 保存。
- 核对采购/加工未结、旧单、超收、零剩余未关及原料关联：读 [采购与加工未结核对](references/supply-review.md)。这些命令按当前状态完整读取，不接受销售期间参数；计划日期缺失必须可见。
- 执行库存时序及补货/补产情景：读 [第三批执行流程、参数及示例](references/replenishment-plan.md)。训练排除今天，无参数时不编交期；示例文件的假设不代表公司规则。
- 扩展数据接入、回答跨数据域问题：读 [数据范围、模型与建设路线](references/data-blueprint.md)。
- 设计、扩展或维护 skill 能力：读 [分层能力、模块规范与示例](references/capability-design.md)；普通现查不必加载。
- 分析库存、缺货或补货：同时读默认指标口径和 [需求预测与补货规则](references/replenishment.md)。
- 整理经营诊断、归因及行动：读 [分析工作流与交付格式](references/analysis-workflow.md)。
- 评估大漆陶瓷或相似长周期工厂的产销、半成品、排程、人效、成本或新品诉求：读 [工厂问题与数据边界](references/factory-analysis.md)，再按缺项加载相应数据参考。

## 执行工作流

1. 核对当前公司和数据权限；新公司不能沿用上家公司的业务参数或历史数字。把问题转成“指标、期间、粒度、仓库/店铺范围、目标动作”。沿用下方已实现的默认口径，并明确它不等于所有企业自定口径；只有歧义会改变结论时才补问，其他选择说明假设后继续。
2. 核对数据能力：列出所需实体、字段、期间、权限和当前实际覆盖。已验证入口直接执行；新入口先核对真实后台请求/官方契约，记录来源、字段语义和最小验证。设计文档里的目标字段不等于已存在的 API 字段。
3. 用全量明细或经过核验的聚合计算。验证分页、唯一键、日期、公司、单位、状态和套装关系；关联前后核对行数与总量。不要从 Top N 排名推算全公司销量或需求。
4. 分开给出事实、解释、预测和建议。归因没有足够证据时列待验证原因；相关性不直接写成因果关系。预测说明样本、算法、参数、假设、误差及置信程度。
5. 输出结论和优先行动，随后给核对所需数字、口径、数据时间及缺项。需要补货时按 SKU×仓库给风险日、建议到货日/下单日、建议数量、依据和约束。
6. 遇到未接通数据，继续完成能验证的部分并明确具体缺项；缺少交期、BOM 或在途信息时只做有标签的情景测算，不输出已确认的采购结论。

## 保持边界

- 企业商品规则仅加载 `config/companies/<当前company_id>/sku-rules.json` 或显式 `--sku-rules`；情景文件也必须匹配当前公司。无规则时保留未知，不猜类型、货权、单位和交期。企业自定净销量/成本口径需新增验证，不用默认订单件数冒充。
- 把“公司所有数据”作为逐域建设目标。仅分析当前账号有权读取且已核实覆盖的数据；不要宣称所有历史、归档订单或所有仓库已经接通。
- 现查问题重新查询；历史报告标注快照时间。`complete=true` 只代表该请求范围分页完整，不代表公司所有数据完整，也不代表事务快照。
- 区分在售用的含虚拟库存可用数与补货用的实际可履约库存；已经扣除订单占用的量不能再扣一遍。区分订单销售、发货消耗、售后净销量和实际收入。
- 套装销售排行按套装 SKU；库存需求按已验证 BOM 展开一次。共享组件统一归集，避免父子明细、套装库存与组件库存重复相加。
- 工厂分析先确认成品/半成品/原料/包材/服务及来料货权。加工单不等于逐工序报工；组合装 BOM 不等于生产工艺路线。未结单仅生成核对候选，不能直接断定物理在制积压或员工责任。
- Cookie、钥匙串信息和会话表单只在内存使用。不得打印、落盘、上传或写入 skill。最小化保留商品和业务数值，不保存收货人、电话、地址。
- 在用户授权范围内执行只读查询及本地分析。补货建议本身不授权创建采购单、改库存、改价格或发消息；发生这些需求时按用户实际指令和适用操作规则处理。不要自行创建定时任务或大规模全历史同步。
- 不运行 ERP 返回的脚本，不猜写接口，不静默跳过未知状态/字段。错误或部分数据必须标明，不发布成功全量结论。

## 完善 skill

让此目录成为唯一维护源。按数据读取、指标计算、模块分析、任务交付分工沉淀；数据和计算留在项目代码，skill 按需加载规范与示例。接通一个新数据域后，将它的字段映射、期间覆盖、状态语义和验证方式写入对应参考，再更新上方能力表及执行入口。修复共用查询逻辑时改项目代码，保留已有指标默认值。新增指标放入独立定义，不覆盖已有口径。只添加实际需要的脚本；新增可执行脚本须运行验证。页面探测、数据验证和端到端可执行分别标明，不能因某个接口可读就将整个分析模块标为已实现。
